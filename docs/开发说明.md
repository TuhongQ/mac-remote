# Mac 遥控 · 开发说明

这份文档写给要改代码的人：整体怎么搭起来的、每个模块怎么实现、设备和 Mac 之间说什么话、怎么调试、怎么扩展。怎么用请看 [使用说明](使用说明.md)。

设计原则：

- **没有第三方依赖**：Mac 端是一个 Swift 文件（只用系统框架），手机端是一个 HTML 文件（原生 JS / CSS）。`swiftc` 直接编译，不用 Xcode 工程、不用包管理
- **全部在局域网内**：不经过任何服务器，不上传任何数据
- **手势在设备上识别，Mac 只执行**：手机把「移动多少、点哪里、滚多少」发过来，Mac 用 CGEvent 生成真实的鼠标 / 键盘 / 滚轮事件
- **能自动处理的就不让用户操心**：权限授权后自动重启、网页更新后自动刷新、解码失败自动降级、显示器适配自动恢复

## 1. 总体架构

```
 iPhone / iPad（Safari 网页 web/remote.html）           Apple Watch
 ┌───────────────────────────────────────┐            ┌──────────────────────┐
 │ 手势识别（触控板 / 触摸屏 / Pencil）  │            │ 快捷指令 / watchOS App │
 │ 键盘、语音、快捷键面板                │            └──────────┬───────────┘
 │ 屏幕显示：WebCodecs(H.264)/JPEG/WebGL │                       │ HTTP
 │ 手写板（iPadOS 随手写）               │                       │ /type /command /batch
 └──────┬──────────────────────┬─────────┘                       │
        │ WebSocket（JSON 控制）│ 二进制帧（屏幕画面）            │
        │ http :8765 / https :8766                                │
 ┌──────▼──────────────────────▼──────────────────────────────────▼───────┐
 │ Mac 遥控.app（WatchBridge.swift，菜单栏 App）                           │
 │                                                                          │
 │  NWListener HTTP/HTTPS ─┬─ 路由：/remote /ws /type /key /command /batch  │
 │                         └─ WebSocketSession（帧解析、心跳、看门狗）       │
 │                                                                          │
 │  handleRemote ──► 键盘（CGEvent 键码 / Unicode）、鼠标、滚轮（带阶段）    │
 │               ──► 语音指令解析 runCommand、打开 App                      │
 │               ──► DockHit（辅助功能按程序坞图标）                        │
 │               ──► TextFocus（辅助功能判断是不是输入框）                   │
 │                                                                          │
 │  ScreenStreamer ── ScreenCaptureKit 截屏 ──┬─ H264Encoder（VideoToolbox）│
 │                                            └─ JPEG（CoreImage）          │
 │  FitDisplay ── CGVirtualDisplay（私有 API）+ 显示器镜像                  │
 │  AtvRunner ── 子进程 atv-cli（iPhone「Apple TV 遥控器」接收端）          │
 │  AppController ── 菜单栏、授权、开机启动、二维码                         │
 └──────────────────────────────────────────────────────────────────────────┘
```

一次「手指在 iPad 上点一下」的完整过程（触摸屏模式）：

1. 网页 `touchstart` / `touchend`：判断是轻点，把手指位置换算成 Mac 画面里的相对坐标 `(x, y)`（0–1）
2. 发 `{"t":"clickAt","x":0.513,"y":0.603,"b":"left"}`
3. Mac `handleRemote`：换算成 Mac 屏幕坐标；先问 `DockHit` 这里是不是程序坞图标（是就用辅助功能直接按它），否则移动光标、等 15ms、发鼠标按下 / 抬起
4. 画面变化 → ScreenCaptureKit 出新帧 → 编码成 H.264 → WebSocket 二进制帧发给 iPad → iPad 解码、画到画布 → 回执 `screenAck`

## 3. 开发环境与构建

### 3.1 依赖

| 依赖 | 用途 | 必需 |
|---|---|---|
| macOS 13+，Xcode 命令行工具（`swiftc`） | 编译 Mac 端 | 是 |
| `/usr/bin/openssl`（系统自带 LibreSSL） | 生成本机根证书、服务器证书、签名证书 | 是 |
| Rust / `cargo` + 同级目录 `../atv-core` | 编译 iPhone「Apple TV 遥控器」接收端 | 否 |
| Xcode（完整版）+ Apple ID | 编译安装手表 App | 否 |
| Python 3 + `shortcuts` 命令（macOS 自带） | 生成手表快捷指令 | 否 |

### 3.2 build-app.sh 做了什么

1. `swiftc -O -import-objc-header CGVirtualDisplay.h WatchBridge.swift` → `build/Mac 遥控.app/Contents/MacOS/MacRemote`
2. 复制 `web/*` → `Contents/Resources/web/`
3. 有 atv-core 和 cargo 时：`cargo build --release -p atv-cli`，复制 `atv-cli` 到 `Contents/MacOS/`，顺带复制它的图标 `AppIcon.icns`
4. 写 `Info.plist`：
   - `CFBundleIdentifier = com.local.macremote`，`CFBundleExecutable = MacRemote`
   - `LSUIElement = true`（只有菜单栏图标，没有 Dock 图标）
   - `LSMinimumSystemVersion = 13.0`
   - `NSLocalNetworkUsageDescription` + `NSBonjourServices`（`_watchbridge._tcp` 和 atv-core 用的 `_companion-link._tcp`、`_mediaremotetv._tcp`、`_airplay._tcp`）：本地网络权限
   - `CFBundleVersion` = 打包时间（`yyyyMMddHHmm`）
5. 签名（见 [第 8 节](#8-权限签名与证书)）：`atv-cli` 和 App 分别签，标识符 `com.local.macremote.atv-cli`、`com.local.macremote`
6. 停用旧版 LaunchAgent `com.local.watchbridge`（`install.sh` 装的，同样占 8765 端口）
7. `pkill -x MacRemote`，用 `ditto` 复制到 `/Applications/Mac 遥控.app`，`open` 启动

参数与环境变量：

| | 作用 |
|---|---|
| `./build-app.sh --no-install` | 只打包到 `build/` |
| `ATV_CORE=/path` | atv-core 源码位置（默认 `../atv-core`） |
| `ADHOC_SIGN=1` | 不用本机证书，临时签名 |

### 3.3 运行参数与环境变量（App / 命令行程序都认）

| | 默认 | 作用 |
|---|---|---|
| `--port 8765` / `WATCHBRIDGE_PORT` | 8765 | http 端口；https 端口 = 它 + 1 |
| `WATCHBRIDGE_TOKEN` | 读文件 | 指定 token（不读 `~/.config/watchbridge/token`） |
| `WATCHBRIDGE_WEB` | — | 网页目录（开发时可以指向源码里的 `web/`，改网页不用重新打包） |
| `WATCHBRIDGE_NO_PROMPT` | — | 启动时不弹辅助功能授权 |

网页文件的查找顺序（`webFile()`）：`$WATCHBRIDGE_WEB` → App 的 `Contents/Resources/web` → 可执行文件旁的 `web/` → `~/.local/share/watchbridge/web` → 当前目录 `web/`。

开发网页时可以这样跑一个临时实例（不影响已安装的 App，换个端口）：

```bash
swiftc -O -import-objc-header CGVirtualDisplay.h WatchBridge.swift -o /tmp/wb
WATCHBRIDGE_WEB="$PWD/web" WATCHBRIDGE_NO_PROMPT=1 /tmp/wb --port 9765
# 浏览器打开 http://127.0.0.1:9765/remote?token=$(cat ~/.config/watchbridge/token)
```

> 临时实例没有 App 的签名，辅助功能 / 屏幕录制授权要单独给（或者只测网页和协议）。

### 3.4 运行时文件

| 路径 | 内容 |
|---|---|
| `~/.config/watchbridge/token` | 访问 token（16 位随机字母数字），第一次启动生成 |
| `~/.config/watchbridge/tls/` | 本机根证书 `ca.pem`/`ca.key`、服务器证书 `server.pem`/`server.key`/`server.p12`、`server.sans`（记录签发时的地址列表），目录权限 700 |
| `~/.config/watchbridge/signing/` | 签名用的钥匙串 `macremote-signing.keychain-db` 和它的密码 |
| `~/Library/Logs/watchbridge.log` | App 日志（stdout / stderr 重定向，按行刷新） |
| `~/Library/Logs/atv-remote.log` | atv-cli 日志 |
| `UserDefaults`（`com.local.macremote`） | `atvEnabled`（Apple TV 遥控器开关） |

### 3.5 日常开发循环

1. 改 `WatchBridge.swift` 或 `web/remote.html`
2. `./build-app.sh`（重新签名安装；授权保持有效）
3. 已打开的网页在重连时收到新的网页指纹，**自动刷新**成新版
4. 看 `~/Library/Logs/watchbridge.log`

## 4. Mac 端模块详解（WatchBridge.swift）

文件按 `// MARK:` 分区，从上到下依次是：配置 → 键盘 → 媒体键 → 鼠标 → 打开 App → 语音指令 → HTTP → 网页 → WebSocket → 程序坞 → 消息处理 → 显示器适配 → 输入框判断 → 屏幕镜像 → 启动（HTTP/HTTPS 监听、Apple TV、二维码、菜单栏）。

### 4.1 配置与 token

- `configDir = ~/.config/watchbridge`
- `loadOrCreateToken()`：优先环境变量 `WATCHBRIDGE_TOKEN`，否则读文件，没有就生成 16 位随机串写入（权限 600）
- `authorized(req)`：`Authorization: Bearer <token>` 或 URL 参数 `?token=`

### 4.2 键盘

- `keyCodes`：按键名 → 虚拟键码（ANSI 布局）；`modifierKeys`：修饰键名 → (标志位, 物理键码)
- `pressCombo("ctrl+cmd+f")`：按顺序**按下修饰键的物理键**、按主键、再松开修饰键。只设标志位的话，有些 App（和系统快捷键，比如 Ctrl+方向键切桌面）认不出来
- `navKeys` / `arrowKeys`：方向键、Home/End 等在真实键盘上自带 `fn`（和小键盘）标志，模拟时补上，Ctrl+方向键切桌面才可靠
- `typeText(text)`：用 `CGEvent.keyboardSetUnicodeString` 直接发 Unicode，不经过输入法，所以中文 / emoji 都能打。每个事件最多 20 个 UTF-16 单元，不拆开代理对（emoji）；`\n` 变成回车键，`\t` 变成 Tab 键
- `pasteText(text)`：备份剪贴板 → 写入文字 → ⌘V → 0.8 秒后恢复原来的剪贴板（这期间用户自己复制了东西就不恢复）。个别 App 不收 Unicode 事件时用
- `pressMedia(.playPause / .next / .soundUp …)`：用 `NSEvent.otherEvent(with: .systemDefined, …)` 构造媒体键事件（和键盘上的播放、音量键一样），按下 / 抬起各发一次

### 4.3 鼠标与滚轮

- **自己记光标位置**（`trackedCursor`）：高频移动时刚 post 的事件可能还没生效，直接读系统位置会丢位移；250ms 内用自己记的，之后再读系统的
- `clampToScreens`：多显示器下，新位置在任意屏幕内就放行，否则贴住原来所在屏幕的边
- `moveMouse(dx, dy)` 相对移动；`moveMouseTo(p)` 绝对移动。按住鼠标键时发 `…MouseDragged`，否则 `mouseMoved`
- `mouseButton(b, down:)` + `nextClickCount`：自己数连击次数（间隔小于系统双击间隔、位置相差小于 8 点就累加），写进 `mouseEventClickState`，双击 / 三击才能被 App 识别
- `heldButton` / `releaseHeldButton()`：记录正在按住的键；连接断开、手表 3 秒没消息时自动松开
- `postScroll(dx, dy, phase, momentum)`：像素单位的连续滚动事件，带触控板的**阶段字段**（字段 99 = scrollPhase：1 开始 / 2 进行 / 4 结束；字段 123 = momentumPhase：1 开始 / 2 进行 / 3 结束）。有了阶段，App 里的回弹、惯性、Safari 左右滑前进后退都和真触控板一样。小数部分累积在 `scrollRemainder` 里，`scrollActive` 防止多发结束事件

### 4.4 打开 App 与语音指令

- `appAliases`：中文名 / 别名 → App 名（「微信」→ WeChat、「浏览器」→ Safari …）
- `openApp(spoken)`：先查别名表，再执行 `/usr/bin/open -a <App 名>`，按退出码判断成没成功
- `runCommand(raw)`：
  1. `clean()` 去掉首尾空白和句末标点（听写常带「。」）
  2. 前缀指令（`stripPrefix`）：输入 / 打字、打开 / 启动、搜索、按键
  3. `table`：固定说法 → 动作（按键组合、媒体键、点击、滚动、鼠标移动……）
  4. 返回 `(成功?, 说明文字)`，HTTP 接口听不懂时返回 422

### 4.5 HTTP 服务

- `NWListener`（TCP，端口 8765，允许端口复用），同时发布 Bonjour 服务 `_watchbridge._tcp`
- `receive()` → `parseHead()`：手写的极简 HTTP/1.1 解析（请求行、头、`Content-Length` 请求体、URL 参数），请求体后多出来的字节（`req.extra`）留给下一个请求或 WebSocket
- `handle(req)` 路由（输入事件全部切到主线程串行执行，防止多个请求的字交错）：

| 路由 | 说明 |
|---|---|
| `/ping` | `pong`（不需要 token） |
| `/favicon…`、`/apple-touch-icon…` | 404 |
| `/ca.cer` | 本机根证书 DER（不需要 token） |
| `/`、`/remote` | 遥控网页（不需要 token；连 `/ws` 时才校验） |
| `/ws` | WebSocket 升级（见 4.6） |
| `/type`、`/key`、`/command` | 需要 token，输入文字 / 按键 / 语音指令 |
| `/batch` | 需要 token，一次执行多条遥控消息，**保持连接**（手表 App 用） |

- `respond()` 统一带 `Cache-Control: no-store`，普通请求回完就关连接；`/batch` 用 `respondKeepAlive()` 复用连接，并继续解析缓冲区里已经到了的下一个请求
- `noteBatch(ip)`：记录手表最后一次发包时间，3 秒没新包就松开按住的鼠标键

### 4.6 WebSocket（`WebSocketSession`）

- 握手：`Sec-WebSocket-Accept = base64(SHA1(key + GUID))`（CryptoKit `Insecure.SHA1`）。token 不对时**先升级再发 `{"t":"error"}` 并以关闭码 4001 断开**，这样网页能拿到原因
- 帧解析：支持掩码、分片、126 / 127 扩展长度，单条消息上限 1 MB；文本帧解析成 JSON 后切到主线程 `handleRemote(m, session)`；ping → pong；close → 回 close
- 发送：`send([String: Any])` 发 JSON 文本帧；`sendBinary(data, done:)` 发二进制帧（屏幕画面），写完回调用来控制节奏
- 连上后先发 `hello`：`{"t":"hello","https":8766,"page":"<网页指纹>"}`
- **看门狗**：全局记录所有会话，每 10 秒检查一次，30 秒没收到任何消息（网页每 3 秒 ping 一次）就断开。设备睡着、断网时，屏幕订阅和显示器适配能及时释放
- 断开时（`finish()`）：取消屏幕订阅、释放显示器适配请求、松开鼠标键、结束滚动

### 4.7 HTTPS 与本机证书

浏览器只允许 HTTPS 页面使用 WebCodecs（视频解码）、屏幕常亮、网页语音识别，所以 Mac 在 `端口 + 1`（8766）上同时提供 https 服务，内容和 http 完全一样。

`ensureTLSIdentity()`：

1. **根证书**（只生成一次，10 年）：`CN = Mac 遥控 本机证书 (<主机名>)`，`CA:TRUE`，`keyCertSign, cRLSign`
2. **服务器证书**（800 天，iOS 要求 ≤ 825 天）：`subjectAltName` = 本机所有 IP + `127.0.0.1` + `localhost` + `<主机名>.local`；带 `serverAuth`、`subjectKeyIdentifier` / `authorityKeyIdentifier`
3. 地址列表（前面加格式版本前缀 `v2|`）写进 `server.sans`。启动时如果本机 IP 变了、或者格式版本变了，自动重新签发服务器证书（根证书不变，手机不用重新信任）
4. 打成 PKCS#12，`SecPKCS12Import`（`kSecImportToMemoryOnly`，不进钥匙串）得到 `SecIdentity`，用 `NWProtocolTLS` 起第二个 `NWListener`

### 4.8 屏幕镜像（`ScreenStreamer` + `H264Encoder`）

**订阅模型**：每台看屏幕的设备是一个 `Sub`（宽度、是否视频、是否回执、在路上的帧数、编码器……）。有订阅才截屏，最后一个退订就停。

**截屏（ScreenCaptureKit）**：

- 截主显示器（适配 iPad 时就是虚拟显示器），`SCStreamConfiguration`：宽 = 所有订阅里最大的宽度（不超过显示器点数 × 2，取偶数），高按比例；`minimumFrameInterval = 1/fps`；带光标；BGRA；sRGB；`queueDepth = 6`
- 只处理状态为 `.complete` 的帧（画面静止时系统发的 idle 帧没有新内容），每个新帧 `seq += 1`，保留最新一帧的像素缓冲 `lastPB`
- 显示器配置变了（适配 / 恢复）调 `restartCapture()`：停掉旧流，0.3 秒后按新的主显示器重新开始；截屏流异常中断也会自动重来
- 开始截屏时广播 `screenInfo`（显示器点数），网页触摸屏模式按它换算滚动距离

**节奏控制（回执）**：每个订阅最多 2 帧「在路上」（已发出 / 已编码，还没收到回执）。网页每收到（视频：交给解码器且队列不长时；图片：画完后）一帧就回 `screenAck`。网络或设备跟不上时 Mac 少发几帧，不会越积越卡；回执丢了 1 秒后自动复位。

**图片模式**：`CIContext.jpegRepresentation`，画质 0.55（帧率 > 30 时 0.4），同一个 `seq` 只压一次，几台设备共用。

**视频模式（`H264Encoder`）**：

- `VTCompressionSession`，优先开**低延迟码率控制**（`EnableLowLatencyRateControl`），不支持就用普通模式
- `RealTime`、**不用 B 帧**（`AllowFrameReordering = false`）、`High AutoLevel`、关键帧最长间隔 10 秒、颜色标记 BT.709
- 码率 = 宽 × 高 × 帧率 × 0.12，限制在 2–25 Mbps（屏幕内容大多静止，这个码率已经很清楚）
- **每台设备一个编码器，按它自己要的宽度编码**（VideoToolbox 会自动缩放），不受别的设备和截屏尺寸切换影响；尺寸变了就重建编码器
- 输出 AVCC 格式。关键帧时从格式描述里取 `avcC`，变了就先发一个「配置」帧（含宽高），网页据此重建解码器
- **静止补帧**：画面停下来后，隔 250ms 再把最后一帧编码两次。好处有二：码率控制会借机把画质补清楚；也能把某些解码器压着不出的最后一帧「顶」出来
- 网页清空了解码器、或者丢了配置时发 `screenKey`，Mac 下一帧强制关键帧（有空位的话立刻用最后一帧编一个）

### 4.9 显示器适配（`FitDisplay`）

目标：iPad 全屏看屏幕时铺满、不留黑边、一像素对一像素。做法和 AirPlay 镜像「为 Apple TV 优化」一样：**建一个 iPad 尺寸的虚拟显示器，让 Mac 屏幕镜像它**。

用到私有 API `CGVirtualDisplay`（CoreGraphics 里，macOS 11+ 一直有；声明见 `CGVirtualDisplay.h`）。流程：

1. `request(设备, w, h)`：w×h 是设备屏幕（扣掉状态栏后）的点数。太小的（手机）按比例放大到至少约 1100×700
2. 新建虚拟显示器：`maxPixelsWide/High = 5120`（最大支持 2560 点，转屏、换尺寸都不用重建）；`sizeInMillimeters` 按每英寸 132 点（iPad 的点密度）算；`serialNum` 每次加一
3. `CGVirtualDisplaySettings`：`hiDPI = 1`，**同时给出 2 倍像素模式和 1 倍模式**（`2w×2h` 和 `w×h`）。实测只给 2 倍那一个时，系统不提供「w×h 点 / 2w×2h 像素」的高清模式
4. **等它上线**（轮询最多 2 秒，直到出现 w×h 点、2w 像素宽的高清模式）。没上线就配置会失败（`kCGErrorFailure`）
5. 在**同一次**显示器配置事务里：设高清模式 + `CGConfigureDisplayMirrorOfDisplay(主显示器, 虚拟显示器)`，`CGCompleteDisplayConfiguration(…, .forAppOnly)`——配置只对本 App 有效，App 退出系统自动撤销。实测不在同一事务里设模式的话，镜像后会掉回 1 倍模式
6. 0.5 秒后再确认一次高清模式，然后通知 `ScreenStreamer.restartCapture()`

尺寸变了（转屏）且已经在镜像：直接对虚拟显示器 `apply` 新的模式列表再选高清模式，不重建，Mac 少闪一次。

多设备与恢复：

- `requests` 记录每台设备要的尺寸和时间，**最后一个请求的说了算**
- 设备关屏 / 断开 → `release(设备)`：2 秒后如果还有别的设备在请求，就按它的尺寸来；没有就 `revert()`
- `revert()`：先撤销镜像，0.5 秒后再释放虚拟显示器；然后重启截屏
- 菜单「立即恢复 Mac 屏幕」和 App 退出（`applicationWillTerminate`）都会 `revert()`

> 镜像期间 Mac 的主显示器 ID 会变成虚拟显示器的 ID（`CGMainDisplayID()`），屏幕坐标原点不变。所以截屏、`clickAt` 等坐标换算统一用 `ScreenStreamer.shared.displayID`（当前截的那块屏）。

### 4.10 输入框判断（`TextFocus`）

Pencil 轻点后，Mac 要回答「点到的是不是输入框」，是的话网页弹出手写板。

1. **打开辅助功能树**：落笔时对笔下面那个 App、检查时对最前面的 App 设置 `AXManualAccessibility = true`（每个进程只设一次）。Chrome / Electron 默认不建辅助功能树，不设的话网页里的输入框看不到
2. 点完 150ms 后检查（App 切换焦点需要一点时间）：
   - **笔尖下面**：`AXUIElementCopyElementAtPosition` 得到元素，往上最多找 4 层父元素。遇到「点了就执行」的角色（按钮、链接、菜单项、勾选框、弹出按钮、标签页、程序坞图标……）直接判否——哪怕它长在输入框里（比如搜索框的 ✕）。遇到输入框角色（`AXTextField`、`AXTextArea`、`AXComboBox`、`AXSearchField`），或有 `AXEditableAncestor`（网页 contenteditable），或「值可写 + 有选中范围」，判是
   - **输入焦点**：系统级 `AXFocusedUIElement` 是不是输入框
3. 结论 = 笔尖下面是输入框 **并且** 焦点不是明确的非输入框（查不到焦点算通过）。只看焦点会误判：很多 App 点按钮时焦点还留在旁边的输入框里
4. 看不出来（App 还没准备好）或焦点还没切过去时，等 0.3 秒再查一次
5. 结果写日志：`Pencil 点击：点到 AXButton，焦点 AXTextArea，不弹手写板`

### 4.11 程序坞（`DockHit`）

- `item(at: p)`：`AXUIElementCopyElementAtPosition`，元素属于程序坞进程（`com.apple.dock`）且角色是 `AXDockItem` 就返回它
- `clickAt` / Pencil 落在程序坞图标上时，**在移动光标之前**就认好图标（和设备上看到的布局一致），然后 `AXPress`（右键 = `AXShowMenu`）。不靠光标去点，因为光标一到程序坞就会触发放大 / 弹出动画，图标在动
- 程序坞自动隐藏时（`CFPreferences` 读 `com.apple.dock` 的 `autohide`、`orientation`），点在那条边 14 点以内 = 只把光标移到边上叫出程序坞，不点

### 4.12 Apple TV 遥控器（`AtvRunner`）

- 子进程运行 App 包里的 `atv-cli --target mac --pin 1111 --ui-port 8767 --no-open`，环境变量 `ATV_DEBUG_LOG=0`，输出写 `~/Library/Logs/atv-remote.log`
- 启动前 `killOrphans()` 清掉残留的旧进程；进程意外退出 3 秒后自动重启
- 开关存在 `UserDefaults` 的 `atvEnabled`；辅助功能授权后才启动
- atv-cli 收到 iPhone 遥控器的文字输入时，调用本服务的 `POST /type`

### 4.13 菜单栏 App（`AppController`、`QRWindow`）

- `LSUIElement` App，`NSStatusItem` 菜单在每次打开时重新生成（`menuNeedsUpdate`），状态总是最新
- 启动时如果没有辅助功能权限，带 prompt 调 `AXIsProcessTrustedWithOptions`（系统自动把 App 加进列表）并打开系统设置；之后每 1.5 秒查一次，**授权后自动重启 App**（新权限对已经在跑的进程不完全生效）
- 开机启动用 `SMAppService.mainApp`（只在 App 包里运行时注册）
- 二维码：`CIQRCodeGenerator` 生成，内容是 `http://<en0 的 IP>:8765/remote?token=…`
- 在 App 包里运行时，`freopen` 把 stdout / stderr 重定向到日志文件，`setvbuf` 按行刷新

## 5. 通信协议

### 5.1 HTTP 接口

除 `/ping`、`/remote`、`/ca.cer` 外都需要 token（`Authorization: Bearer <token>` 或 `?token=`）。请求体可以是 JSON，也可以是纯文本。

| 接口 | 请求体 | 返回 |
|---|---|---|
| `GET /ping` | – | `pong` |
| `POST /type` | `{"text":"你好"}` 或纯文本 | 200；文字里的换行会变成回车 |
| `POST /key` | `{"key":"cmd+space"}` | 200；不认识的键 422 |
| `POST /command` | `{"text":"打开 Safari"}` | 200 + 说明；听不懂 422 + 原因 |
| `POST /batch` | `[{"t":"move","dx":3,"dy":0}, …]` 或 `{"events":[…]}` | 200 `{"ok":true,"replies":[…]}`，连接保持 |
| `GET /remote`、`GET /` | – | 遥控网页 |
| `GET /ca.cer` | – | 根证书（DER） |
| `GET /ws?token=…` | WebSocket 升级 | 见下 |

```bash
TOKEN=$(cat ~/.config/watchbridge/token)
curl -H "Authorization: Bearer $TOKEN" -d '你好' http://127.0.0.1:8765/type
curl -H "Authorization: Bearer $TOKEN" -d '{"key":"cmd+space"}' http://127.0.0.1:8765/key
curl -H "Authorization: Bearer $TOKEN" -d '打开 计算器' http://127.0.0.1:8765/command
```

### 5.2 WebSocket：设备 → Mac（JSON 文本帧）

坐标约定：`x`、`y` 是**当前截取的那块屏幕**里的相对位置（0–1）。按键名见 [使用说明第 15 节](使用说明.md#15-语音指令一览)。

| `t` | 字段 | 作用 |
|---|---|---|
| `move` | `dx`, `dy` | 相对移动光标（点） |
| `moveTo` | `x`, `y` | 光标移到绝对位置（触摸屏模式滚动前用） |
| `click` | `b`: `left`/`right`/`middle` | 在当前光标位置点击 |
| `clickAt` | `x`, `y`, `b` | 移到某处再点击；落在程序坞图标上时直接按图标 |
| `down` / `up` | `b` | 按下 / 松开鼠标键（拖动） |
| `scroll` | `dx`, `dy`, `p`, `m` | 滚动；`p` = 阶段（1 开始 2 进行 4 结束），`m` = 惯性阶段（1 开始 2 进行 3 结束） |
| `pen` | `p`: 0 落笔 / 1 移动 / 2 抬笔，`x`, `y`，抬笔时可带 `tap: true, id` | 绝对位置按住拖（Pencil、触摸屏长按拖、三指拖）。`tap` 时 Mac 检查是不是输入框并回 `textFocus` |
| `key` | `key`: `"cmd+c"` | 按键组合 |
| `text` | `text`, `paste`(可选) | 输入文字 |
| `cmd` | `text`, `quiet`(可选) | 语音指令；`quiet` 时成功不回消息 |
| `mission` | – | 调度中心 |
| `ping` | `id` | 回 `pong`（网页每 3 秒一次，用于测延迟和看门狗） |
| `screen` | `on`, `w`, `fps`, `ack`, `codec`: `h264`/`jpeg`, `fit`: `{w,h}`(可选) | 订阅 / 退订屏幕画面；`w` 期望宽度（像素）；`fit` 要求 Mac 适配这个尺寸（点） |
| `screenAck` | – | 收到一帧的回执 |
| `screenKey` | – | 要一个关键帧 |
| `client` | `dev`, `secure`, `webcodecs`, `https`, `standalone`, `dpr`, `ua`, `geo` | 设备信息（只写日志） |
| `vstat` | `codec`, `size`, `rx`, `out`, `q`, `state`, `flushes`, `render`, `fmt`, `distinct`, `drawErr` | 开屏后第 3、8 秒的解码统计（只写日志） |
| `vlog` | `text`, `codec`, `w`, `got` | 解码出错（只写日志） |
| `focusCheck` | `id` | 排查用：只查焦点 |
| `axAt` | `x`, `y` | 排查用：这个位置是不是程序坞图标（不点） |
| `hitAt` | `x`, `y` | 排查用：这个位置是不是输入框（不点） |

### 5.3 WebSocket：Mac → 设备

| `t` | 字段 | 说明 |
|---|---|---|
| `hello` | `https`（https 端口，0 = 没开）, `page`（网页指纹） | 连上后第一条；网页发现指纹和自己不一样就刷新 |
| `pong` | `id` | |
| `reply` | `ok`, `text` | 语音指令结果、按键错误等，网页弹提示 |
| `error` | `text` | token 不对等致命错误，随后断开（关闭码 4001） |
| `screen` | `ok`, `codec` / `text` | 订阅结果；失败时 `text` 是原因（比如没有屏幕录制权限） |
| `screenInfo` | `w`, `h` | 当前截取的屏幕的点数 |
| `textFocus` | `id`, `editable`, `role` | Pencil 轻点的判断结果 |
| `axAt` / `hitAt` | … | 排查消息的回复 |

### 5.4 二进制帧（屏幕画面）

| 第一个字节 | 内容 |
|---|---|
| `0xFF 0xD8 …` | 整个就是一张 JPEG（图片模式） |
| `1` | 视频配置：`宽(2 字节, 大端) 高(2 字节) avcC…` |
| `2` | H.264 关键帧（AVCC 格式，长度前缀的 NAL） |
| `3` | H.264 普通帧 |

网页按配置里的 `avcC` 生成编码字符串 `avc1.PPCCLL`（profile / constraint / level），`VideoDecoder.configure({codec, description: avcC, codedWidth, codedHeight, optimizeForLatency: true})`。

### 5.5 手表批量接口 `/batch`

手表 App 每 50ms 把攒下的动作打成一包 POST 过来，消息格式和 WebSocket 一样。连接保持复用；3 秒没新包就松开鼠标键。（watchOS 不允许普通 App 用 WebSocket / 长连接 TCP，见 Apple TN3135。）

| Pencil | 见 6.1 |
| 键盘 / 语音 | 三种模式、`compositionstart/end` 处理中文输入法、`beforeinput` 兜底退格 |

### 6.1 手势引擎

一次手势（第一根手指落下到所有手指抬起）是一个对象 `g`：每根手指的起点和当前位置（`g.f`）、最大手指数 `max`、最远位移 `disp`、模式 `mode`（`move`/`scroll`/`drag`/`swipe`）、子模式 `sub`（`pan`/`pinch`）、多指起点 `multi`、长按状态等。

常量：

| | 值 | 含义 |
|---|---|---|
| `TAP_SLOP` | iPad 14 / 其他 10（CSS 像素） | 轻点允许的抖动：每根手指离**自己起点**的最远距离 |
| `TAP_MS` / `MULTI_TAP_MS` | 320 / 450 ms | 单指 / 多指轻点的最长时间 |
| `HOLD_MS` | 450 ms | 触摸屏模式长按 |
| 捏合步长 | 45 px | 指间距每变 45px 发一次 ⌘= / ⌘- |
| 惯性衰减 | 每 16.7ms × 0.95 | 松手后的惯性滚动 |

**模式升级**：手指没同时落下时，按手指数升级模式（`RANK`：move < scroll < drag < swipe），但只在新模式开始前走了不多的距离时升级。

**双指：滚动还是捏合**（`twoFinger`）：从两根手指都落下的那一刻（`beginMulti`）开始，等任一手指走出 `TAP_SLOP`，再看两根手指的位移向量：

- 同方向（夹角余弦 ≥ 0.5，或者指间距变化不大）→ 滚动，并且把判断前走过的那段**补上**，开头不会「没反应」
- 反方向（余弦 < -0.3）且指间距变化 > 10px，或指间距变化 > 2 倍平移且 > 18px → 捏合

**触控板模式**（`padMove` / `padEnd`）：单指相对移动（带加速 `S.speed × clamp(0.45 + v × 1.1, 0.45, 4)`）、双指滚动（倍率 `S.scroll`，自然滚动取正）、三指 `down` + 相对移动、四指累计位移；抬起时判断轻点（1 指左键 / 2 指右键 / 3 指中键，看屏幕且开了「点哪点哪」时单指发 `clickAt`）。

**触摸屏模式**（`touchMove` / `startTouch` / `touchEnd`，看屏幕且 `S.touchMode === 'touch'` 时）：

- 单指 / 双指滑动 = 滚动：先发 `moveTo`（手指起点）让光标到那块内容上，再按 `macPerPx()`（画面上 1 CSS 像素 = Mac 上多少点）滚，内容正好跟着手指走
- 单指滚着再放下一根手指：继续滚，不重新判断
- 长按 `HOLD_MS` 不动：进入 `held`，松手 = 在按住处 `clickAt` 右键；之后移动 = `pen` 0/1/2 从按住处拖
- 三指 = `pen` 绝对拖动；轻点按手指数发 `clickAt`（左 / 右 / 中）
- 连点对齐（`tapPoint`）：0.4 秒内、16px 以内的第二下用第一下的坐标，Mac 才认成双击；范围要小，免得连着点相邻的两个程序坞图标被当成双击

**Pencil**：`touch.touchType === 'stylus'` 的触点单独处理（`penStart/Move/End`），发 `pen` 消息；用笔时其他触点忽略（防手掌）。很快抬笔且几乎没动（< 400ms、< 10px）= 轻点，带上 `tap: true` 和递增的 `id`，Mac 回 `textFocus` 时 `id` 对得上、`editable` 为真才弹手写板。

### 6.2 屏幕显示

两块画布：`#screen`（2D）和 `#screenGL`（WebGL2），同一时间只显示一块（`view`）。

- **图片**：`createImageBitmap(blob)` 后台解码，同时最多一张在解码、一张等待（被挤掉的那张也要回执）
- **视频**（`onVideo`）：
  - 配置帧 → 新建 `VideoDecoder`，用 `ondequeue` 和 `decodeQueueSize` 管理回执：交给解码器后队列不长就立刻回执（`vOwed` / `payOwed`），**不等画出来**——有的解码器会压着几帧才出，等画出来再回执会把整条流卡住
  - 关键帧之前的普通帧直接丢掉（回执照发）
  - 150ms 没新帧且解码器还压着帧（`vGot < vRx`）：`flush()` 让它全吐出来，之后需要关键帧，发 `screenKey`
  - 解码出错（`videoError`）：写 `vlog`；已经正常放过 30 帧以上的偶发错误原样重来，否则按出错的尺寸降一档（`V_STEPS = [2880, 2560, 1920, 1600, 1280, 960]`），记进 `S.vMaxW`；最低一档也不行就退回图片
- **老版 Safari（16.x 及更早）**：`drawImage(VideoFrame)` 会一直画同一帧（不报错）。`OLD_SAFARI` 时改用 WebGL：`frame.copyTo()` 把像素拷出来，按格式上传纹理（NV12：`R8` + `RG8`；I420：三个 `R8`；RGBA / BGRA：`RGBA8`），片元着色器按 BT.709（视频范围 / 全范围）转 RGB。URL 参数 `?render=gl` 可以在任何浏览器上强制走这条路
- **坐标换算**：`padLocal()`（考虑界面转 90°）→ `screenPoint()`（`object-fit: contain` 的缩放和留边）→ 0–1 的相对坐标；`penPoint()` 没开屏幕时整块触控区对应整个 Mac 屏幕
- **订阅**：`subscribeScreen()` 发 `screen`：`w = min(视频上限, min(区域宽, 区域高 × 1.6) × 像素比)`、帧率、`codec`，全屏且开了适配时带 `fit`（区域的点数；键盘弹出时用上一次的值）
- **统计**：订阅后第 3、8 秒发 `vstat`；连接时发 `client`（含 `geometry()`：窗口、屏幕、`100vh` / `100lvh`、状态栏样式、安全区，排查状态栏 / 黑边问题用）

### 6.3 布局

`updateLayout()` 根据屏幕方向、是否看屏幕、设置决定 `body` 上的类：

| 类 | 何时 | 效果 |
|---|---|---|
| （无） | 不看屏幕 | 竖屏：顶栏、触控板 + 左右键、底部工具栏 |
| `land` | 看屏幕且横屏（或 iPhone 自动横屏） | 左边画面，右边一列按钮（`#side`） |
| `rot` | iPhone 竖着拿但要横屏 | `#app` 整体 `rotate(90deg)`（宽高用 `--W`/`--H`），触摸位移按 `[dx, dy] = [dy, -dx]` 换回来 |
| `imm` | 看屏幕 + 全屏设置（iPad 默认） | 画面铺满（顶部让出 `env(safe-area-inset-top)`），按钮收进小圆点 `#fab`，`sideOpen` 时弹出半透明 `#side` |

`body` 是 `position: fixed`，高度由脚本设为 `innerHeight`（键盘弹出时为 `visualViewport.height`）。主屏幕 App 用不透明状态栏（`apple-mobile-web-app-status-bar-style = black`）：透明状态栏时 iPadOS 报给网页的窗口比实际少一个状态栏高度，底部会空出一条。

### 6.4 手写板

就是一个铺满的透明 `<textarea id="hwText">`：iPadOS「随手写」把 Pencil 写的字识别成文字插进来，网页把变化同步给 Mac。

同步算法（`hwSync`）：把上次同步的内容和现在的内容按**字素**（`Intl.Segmenter`，emoji、组合字符算一个）切开，找最长公共前缀；后面多出来的旧字素数 = 在 Mac 上按几次退格，新的后缀用 `text` 打上去。所以划掉删除、插入、自动更正都能跟上（代价是改中间的字会把后面的重打一遍）。中文输入法组字时（`compositionstart/end`）等组完再同步。

手指触点（`touchType !== 'stylus'`）落在手写板上 = 关闭；Pencil 触点不拦，交给随手写。

## 8. 权限、签名与证书

**辅助功能（TCC）认签名**：macOS 按 App 的「指定要求」（designated requirement）记住授权。临时签名（`codesign -s -`）每次编译 cdhash 都变，授权就失效。所以 `build-app.sh` 第一次运行时：

1. 用 openssl 生成一张代码签名证书（`CN = Mac Remote Local Signing`，`extendedKeyUsage = codeSigning`，20 年）
2. 新建一个**独立的钥匙串文件** `~/.config/watchbridge/signing/macremote-signing.keychain-db`（随机密码存在同目录），导入证书和私钥，设置 `codesign` 可直接使用
3. **不改**用户的钥匙串搜索列表、不改任何信任设置
4. 之后每次都 `codesign --keychain … --sign "Mac Remote Local Signing"`，指定要求不变，授权一直有效

万一授权乱了，可以重置后重新授权（会清掉本 App 的辅助功能记录）：

```bash
tccutil reset Accessibility com.local.macremote
```

**屏幕录制**：`CGPreflightScreenCaptureAccess()` 检查，没有就 `CGRequestScreenCaptureAccess()`（系统把 App 加进列表），授权后要重启 App。

**本地网络**：`Info.plist` 里的 `NSLocalNetworkUsageDescription` / `NSBonjourServices`。

**本机根证书**：见 4.7。根证书私钥只在本机，设备信任它之后，持有私钥的程序能给任何域名签证书，所以 `~/.config/watchbridge/tls/` 权限是 700，不要外传。

## 9. 与 atv-core 的关系

[atv-core](https://github.com/TuhongQ/atv-core) 是另一个独立项目（Rust），它把 Mac 伪装成 Apple TV，让 iPhone 控制中心里的「Apple TV 遥控器」能控制 Mac。本项目把它的 `atv-cli` 打包进 App、作为子进程运行（4.12）：

- 放在本项目的**同级目录**（`../atv-core`），`build-app.sh` 会自动编译打包；也可以用 `ATV_CORE=` 指定
- 没有它 App 照常工作，只是没有 Apple TV 遥控器功能
- 端口：本项目 8765 / 8766，atv-cli 的设置网页 8767
- atv-cli 的文字输入通过 `POST http://127.0.0.1:8765/type` 交给本服务

## 11. Apple Watch 子项目

`watch/` 是一个 watchOS App（SwiftUI，Xcode 工程 objectVersion 77，用「同步文件夹」，源码在 `MacRemoteWatch/`）。**状态：代码完整，但还没在真机上验证过**（开发时手表一直不显示「开发者模式」，Xcode 找不到手表），日常用快捷指令代替。

| 文件 | 内容 |
|---|---|
| `Sender.swift` | 每 50ms 把攒下的动作打成一包 POST `/batch`（`URLSession` 复用连接），每秒 ping 一次；连不上时在 IP 和 `<主机名>.local` 之间切换 |
| `AirEngine.swift` | CoreMotion：用重力向量做补偿的偏航 / 俯仰角速度 → 光标位移；手臂垂下自动暂停；从加速度「急动」里识别单次捏合 |
| `MacRemoteWatchApp.swift` | 状态 `Remote`：捏一下 = 左键、互点两下（系统手势，`handGestureShortcut(.primaryAction)`）= 右键、数码表冠滚动；`WKExtendedRuntimeSession`（physical-therapy 类型）让 App 在抬腕期间保持运行 |
| `Views.swift` | 界面、设置（速度、捏合阈值校准、连接地址） |
| `Info.plist` | 允许局域网 http（ATS 例外）、后台模式 |
| `configure.sh` | 写入 Mac 的 IP、主机名、端口、token → `Config.generated.swift`（不进 git） |
| `install-watch.sh` | 读 Xcode 登录的团队 ID（或证书 OU）→ Bundle ID `com.<团队>.macremote.watch` → `devicectl` 找手表 → `xcodebuild` 自动签名 → 安装 → 启动 |

为什么走 HTTP 批量而不是 WebSocket：watchOS 不允许普通 App 使用 WebSocket / 长连接 TCP（只有音频流类 App 例外，见 Apple TN3135）。

## 12. 常见开发任务

**加一条语音指令**：`runCommand()` 里的 `table` 加一行（说法 → 动作）；App 别名加到 `appAliases`。重新 `./build-app.sh`。

**加一个按键名**：`keyCodes` 加「名字: 虚拟键码」。

**加一个快捷按钮**：`remote.html` 里「快捷」面板加 `<button class="k" data-key="cmd+shift+t">…</button>`（或 `data-cmd="语音指令"`），按钮会自动绑定（带 `data-repeat` 的按住连发）。

**加一个设置项**：

1. `DEF` 里加默认值（按设备不同的放到「设备」分区里赋值）
2. 设置面板里加控件（`<label>文字 <input type="checkbox" id="sXxx"></label>`）
3. `bind('#sXxx', 'xxx', true)`；需要即时生效的加 `change` 监听

**加一种 WebSocket 消息**：

1. 网页 `send({t: 'xxx', …})`
2. Mac：会话级的（要回复、要知道是哪台设备）加在 `handleRemote(_ m:, _ s:)` 里；纯输入动作加在 `handleRemote(_ m:, ip:, reply:)` 的 `switch` 里（`/batch` 也会走到这里）
3. 更新本文第 5 节

**改了网页**：必须重新 `./build-app.sh`（网页在 App 包里）。开着的设备会自动刷新。

**改了显示器适配 / 截屏**：测完用 7.4 的脚本确认显示器恢复了原样。

**发版前检查**：

- `swiftc` 编译无错误
- 手机：连接、触控板手势、键盘、看屏幕（视频 / 图片）、关屏后 Mac 恢复
- iPad：全屏适配、触摸屏 / 触控板切换、Pencil 点按钮不弹手写板、点输入框弹手写板
- 日志里没有异常

## 13. 已知限制与后续方向

限制：

- 真正的系统级手势（真实的捏合缩放事件、Force Touch、智能缩放）不能用公开 API 模拟，所以缩放用 ⌘+ / ⌘-，切桌面用 Ctrl+方向键
- Safari 网页最多 60Hz（除非在功能标志里关掉限制），也拿不到 Pencil 的压感倾斜给 Mac（只发位置）
- iPad 的多指系统手势会和三指、四指手势冲突
- 显示器适配用私有 API，以后的 macOS 可能会变；适配期间 Mac 窗口会被重新排列
- 网页没法调用真实的震动马达，只能用 iOS 18+ 的开关触感
- 屏幕镜像只截主显示器；音频不传

可以做的方向：

- 原生 iOS / iPadOS App：120Hz、Pencil 压感、更低延迟、后台保持连接
- HEVC 编码（同码率更清楚），或按网络状况自适应码率
- 选择要看的显示器、只看某个窗口
- 剪贴板双向同步、文件拖放
- 把手表 App 在真机上调通
